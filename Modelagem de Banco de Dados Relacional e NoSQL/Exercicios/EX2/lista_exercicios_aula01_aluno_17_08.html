Parte I — Questões Objetivas

Questão 1 Fácil

Antes dos Sistemas Gerenciadores de Banco de Dados (SGBD), cada aplicação mantinha seus próprios arquivos de dados, o que gerava problemas estruturais nas organizações. Assinale a alternativa que apresenta o principal conjunto de problemas que os SGBD foram criados para resolver:

  • A) Alto custo dos discos rígidos e a lentidão dos compiladores da época.
  • B) Redundância e inconsistência de dados, isolamento de dados, dificuldade de acesso e falta de garantias de integridade e recuperação.
  • C) O excesso de normalização aplicado aos arquivos texto, que impedia a leitura sequencial.
  • D) A necessidade de substituir imediatamente todos os bancos relacionais por bancos NoSQL.
  • E) A ausência de interfaces gráficas nos sistemas operacionais, que impedia o cadastro de clientes.

Questão 2 Fácil

No modelo relacional proposto por Edgar Codd, existe uma correspondência formal entre os termos teóricos e a visualização tabular que utilizamos na prática. Assinale a alternativa que apresenta essa correspondência de forma correta:

  • A) Relação ↔ coluna; Tupla ↔ linha; Atributo ↔ tabela.
  • B) Relação ↔ tabela; Tupla ↔ linha; Atributo ↔ coluna.
  • C) Relação ↔ linha; Tupla ↔ coluna; Atributo ↔ célula.
  • D) Relação ↔ banco de dados; Tupla ↔ SGBD; Atributo ↔ índice.
  • E) Relação ↔ tabela; Tupla ↔ coluna; Atributo ↔ linha.

Questão 3 Fácil

No modelo relacional, o conceito de domínio é fundamental para a integridade dos dados. Assinale a alternativa que o define corretamente:

  • A) É a quantidade de tuplas armazenadas em uma relação em um dado instante.
  • B) É o conjunto de valores permitidos para um atributo, como datas válidas ou inteiros positivos.
  • C) É o nome oficial de uma tabela dentro do esquema do banco de dados.
  • D) É sinônimo de chave estrangeira quando ela referencia outra tabela.
  • E) É o grau de uma relação, ou seja, o número de colunas que ela possui.

Questão 4 Médio

Considere a relação Cliente(id_cliente, nome, cpf, email), em que id_cliente é um identificador numérico gerado automaticamente pelo banco (chave substituta), e cpf e email são atributos obrigatórios e únicos para cada cliente. Assinale a alternativa correta:

  • A) cpf e email não podem ser chaves candidatas porque são do tipo texto.
  • B) id_cliente é a chave primária, enquanto cpf e email são chaves alternativas que devem ser protegidas por restrições UNIQUE.
  • C) Uma relação pode ter apenas uma chave candidata; as demais devem ser removidas do modelo.
  • D) Toda chave estrangeira deve, obrigatoriamente, referenciar uma chave primária composta.
  • E) A chave substituta deve ser sempre um dado de negócio estável, como o CPF do cliente.

Questão 5 Médio 💻 LEITURA DE CÓDIGO

Considere que o banco LojaVirtual da Aula 01 já foi criado com as tabelas Cliente e Pedido, incluindo a restrição FK_Pedido_Cliente, e que a tabela Cliente contém apenas o cliente com id_cliente = 1 (Maria). Analise o comando abaixo:

INSERT INTO Pedido (id_cliente, status, total)
VALUES (999, 'PENDENTE', 10.00);

Assinale o que acontecerá ao executá-lo:

  • A) O pedido será inserido normalmente, com o nome do cliente preenchido como NULL.
  • B) O comando será rejeitado por violação de integridade referencial (FOREIGN KEY), gerando um erro semelhante ao Msg 547 do SQL Server.
  • C) O SGBD criará automaticamente um novo cliente com id_cliente = 999 para satisfazer a inserção.
  • D) O comando será rejeitado porque a tabela Pedido possui grau maior que o da tabela Cliente.
  • E) O pedido ficará em estado pendente até que um COMMIT confirme a criação do cliente 999.

Questão 6 Médio

Na passagem do modelo conceitual (ER) para o modelo lógico relacional, existe uma regra padrão para a implementação de um relacionamento 1:N (um-para-muitos), como CLIENTE (1) realiza PEDIDO (N). Assinale a alternativa que descreve essa regra corretamente:

  • A) A chave primária do lado “N” migra como chave estrangeira para o lado “1”.
  • B) Cria-se uma terceira tabela contendo apenas os atributos do relacionamento.
  • C) A chave primária da entidade do lado “1” migra como chave estrangeira (NOT NULL, quando obrigatória) para a tabela do lado “N”.
  • D) Relacionamentos 1:N não podem ser representados no modelo relacional e devem ser simplificados para 1:1.
  • E) As duas entidades devem ser fundidas em uma única tabela para evitar junções.

Questão 7 Médio

Um relacionamento N:M (muitos-para-muitos), como PEDIDO contém PRODUTO, não pode ser implementado diretamente no modelo relacional. Assinale a alternativa que descreve a solução correta e consagrada para esse caso:

  • A) Inserir uma chave estrangeira multivalorada em uma das duas tabelas, separando os valores por vírgula.
  • B) Criar uma tabela associativa (ex.: ITEM_PEDIDO) com chaves estrangeiras para as duas entidades, decompondo o N:M em dois relacionamentos 1:N.
  • C) Duplicar a tabela PEDIDO, criando uma cópia para cada produto envolvido.
  • D) Escolher arbitrariamente um dos lados para receber a chave estrangeira do outro.
  • E) Migrar o relacionamento N:M para uma planilha auxiliar fora do SGBD.

Questão 8 Médio

Considere a tabela MATRICULA abaixo, utilizada para registrar matrículas de alunos em disciplinas:

id_matriculaalunodisciplinasprofessornota
1MariaBD, LP1Prof. Ana; Prof. Carlos8,5; 7,0
2JoãoBDProf. Ana9,0

Essa estrutura viola, imediatamente, qual regra de projeto?

  • A) A 3ª Forma Normal, pois existe dependência transitiva entre aluno e nota.
  • B) A 2ª Forma Normal, pois a chave é composta.
  • C) A 1ª Forma Normal, pois há células com múltiplos valores (grupos repetidos), ferindo a atomicidade.
  • D) A integridade referencial, pois não há chave estrangeira declarada.
  • E) A integridade de entidade, pois id_matricula não pode ser numérico.

Questão 9 Difícil

Considere a relação MATRICULA(id_matricula, cod_disc, aluno, professor, nota) já na 1FN, com chave primária composta (id_matricula, cod_disc). Sabe-se que:

  • aluno depende apenas de id_matricula (o nome do aluno não muda conforme a disciplina);
  • professor depende apenas de cod_disc (a disciplina define o professor, independentemente do aluno);
  • nota depende da chave completa (aluno + disciplina).

Com base nessas dependências, assinale a alternativa correta:

  • A) A relação já se encontra na 3ª Forma Normal, pois todos os atributos dependem da chave.
  • B) A relação viola a 1ª Forma Normal, pois possui chave composta.
  • C) A relação viola a 2ª Forma Normal, pois aluno e professor dependem apenas de parte da chave composta (dependência parcial).
  • D) A relação viola somente a 3ª Forma Normal, pois nota depende de aluno.
  • E) A relação viola a integridade de entidade, pois chaves compostas são proibidas no modelo relacional.

Questão 10 Difícil 💻 LEITURA DE CÓDIGO

Analise o script T-SQL abaixo, executado em um banco recém-criado e vazio:

CREATE TABLE Cliente (
    id_cliente INT IDENTITY(1,1) PRIMARY KEY,
    nome       VARCHAR(100) NOT NULL,
    email      VARCHAR(120) NOT NULL UNIQUE,
    cpf        CHAR(11)     NOT NULL UNIQUE
);
GO

INSERT INTO Cliente (nome, email, cpf)
VALUES ('Maria Silva', 'maria@email.com', '11111111111');

INSERT INTO Cliente (nome, email, cpf)
VALUES ('José Santos', 'jose@email.com', '22222222222');

INSERT INTO Cliente (nome, email, cpf)
VALUES ('Maria Duarte', 'maria@email.com', '33333333333');

Assinale o que ocorrerá na execução do terceiro INSERT:

  • A) Será executado com sucesso, pois o nome “Maria Duarte” é diferente de “Maria Silva”.
  • B) Será rejeitado por violação da restrição UNIQUE sobre email (erro do tipo Msg 2627), pois 'maria@email.com' já existe.
  • C) Será rejeitado por violação de chave estrangeira, pois não existe tabela Pedido correspondente.
  • D) Será rejeitado por violação de uma restrição CHECK de domínio sobre o atributo cpf.
  • E) Será executado com sucesso e sobrescreverá os dados da cliente Maria Silva.

Questão D4 Difícil 💻 ESCRITA DE CÓDIGO
